# Internationalization

Every string a user can read goes through next-intl. The locale is a root param (`src/app/[locale]/`) that `src/proxy.ts` resolves from the `locale` cookie and keeps out of the URL; the supported locales are the `locales` list in `src/lib/i18n/routing.ts`, with one message file per locale in `src/lib/i18n/messages/`.

- Read every user-visible string with `getTranslations` (server) or `useTranslations` (client); a prose literal in JSX is the sign you are about to break this.
- Put each key in every locale's message file in the same change, under a namespace named after the component that reads it (`"HomePage": { "title": … }`); the default locale's file types the keys, so `pnpm typecheck` fails on a key the code uses and that file lacks.
- Render markup inside a message with `t.rich("key", { tag: (chunks) => <tag>{chunks}</tag> })`, never by concatenating strings around `t("key")`.
- Add a locale by adding its entry to `locales` in `src/lib/i18n/routing.ts` and its message file next to the others; nothing else changes.
